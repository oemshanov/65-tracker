# Time Tracker — учёт времени без таймеров

Ничего не нужно запускать и не нужно помнить. Фоновый сборщик сам записывает, чем вы заняты.
Раз в день (по умолчанию утром за вчера) приходит напоминание, и за пару минут день раскладывается
по задачам Jira: в таймлайне или в разговоре с Claude. Затем ворклоги уходят в Jira/Tempo
одной кнопкой или выгружаются для ручного ввода.

```
 ttcollect (Swift, launchd)        tt (Python, stdlib)                    куда
 ─────────────────────────         ──────────────────────────────         ─────────────────────
 активное приложение    ─┐         слоты по 5 мин → блоки                 таймлайн  (tt open)
 заголовок окна          │ SQLite  контекст: Jira-ключ / Figma-файл /     Claude    (/timesheet)
 URL вкладки браузера    ├──────►  чат / сайт / созвон / календарь  ──►   Jira API  (tt push)
 простой / блокировка    │         → задача: ключ > запомнено >           вручную   (tt export)
 кто держит микрофон     │           правило > подсказка Claude
 события Календаря      ─┘         → черновики ворклогов (округл. 15 мин)
```

**Ресурсы:** сборщик — один процесс, около 35 МБ памяти, CPU около нуля. Опрос раз в 10 с,
без скриншотов и OCR; одинаковые подряд состояния склеиваются, поэтому база растёт примерно на 1 МБ
в месяц. Сервер таймлайна поднимается по требованию и сам выключается через 30 минут
после закрытия вкладки.

**Приватность:** всё хранится локально в `~/Library/Application Support/TimeTracker/tt.db`.
Наружу данные уходят в двух случаях: в Jira — только ворклоги после вашего подтверждения;
в Claude — только когда вы сами нажали «Спросить Claude» или позвали `/timesheet`, и только
агрегированные неразобранные фрагменты (название, длительность, примеры заголовков).
Запись, разбивка на блоки, правила, выученные привязки и напоминания работают без Claude
и токенов не тратят. Окна по шаблону скрываются через
`redact_title_patterns`, приложения целиком — через `ignore_bundles`.

### Подобрать локально (без Claude)

Кнопка «✦ Подобрать локально» над неразобранными активностями. Маленькая модель (Ollama + bge-m3)
на этом Маке сравнивает по смыслу название активности с задачами Jira и вашими прошлыми привязками:
«checkout-redesign» ≈ «Редизайн оформления заказа». Ollama запускается только на время подбора и сразу
закрывается, модель выгружается из памяти — в фоне ничего не работает, токены не тратятся.
Подсказки модели помечены «модель локально: …», сами в ворклоги не попадают — их принимаете вы.
Активности, которые модель отнесла к одной задаче, показываются одной карточкой.

Установка (один раз): `brew install ollama`, затем `ollama serve` и в другом окне `ollama pull bge-m3`.

## Работа в Claude Code

Окно Claude всегда называется просто «Claude», поэтому трекер дополнительно читает локальные журналы
сессий Claude Code (`~/.claude/projects`). Из них берутся только метаданные: время реплик, папка
проекта, ветка и название сессии. Текст переписки не сохраняется.

- Пока Claude на переднем плане, время идёт той сессии, где вы последней писали. Блок называется
  так: «Claude Code: Alpha Claude/alpha-proto — Фильтры операций».
- Ключ Jira в ветке (`feature/ALP-12-…`), в папке (`… PRJ-718`) или в названии сессии проставляет
  задачу сам. Если ключа нет, «запомнить» привязывает к задаче весь проект, включая будущие сессии.
- Пока Claude работает, а вы ждёте, не трогая клавиатуру, время засчитывается, пока в сессии идёт
  активность, но не больше 30 минут подряд (`claude.waiting_cap_min`, `claude.count_waiting`).
- Обычные чаты Claude не разбираются: они попадают в «Claude» без подробностей.

## Установка

### Для коллег: «65 tracker.dmg»

Сборка: `./build_dmg.sh` → `dist/65 tracker.dmg` (около 40 МБ). Внутри приложение со своим Python —
Homebrew, Xcode и терминал не нужны. Ничего не ставит на Мак, где собирается.

1. Открыть образ, перетащить «65 tracker» в «Программы».
2. Первый запуск: приложение не нотаризовано, macOS не пустит его сразу. «Готово» → Системные настройки →
   Конфиденциальность и безопасность → «Всё равно открыть». Если пишет «повреждено» —
   `xattr -dr com.apple.quarantine "/Applications/65 tracker.app"`.
3. Приложение само раскладывает код в `~/Library/Application Support/TimeTracker`, ставит автозапуск
   и утреннее напоминание, просит «Универсальный доступ» (плашка «Выдать доступ»).
4. Jira: «Открыть таймлайн» → «Подключить Jira», токен — в Связке ключей.

Нейросеть для подбора задач в образ не входит: её можно скачать в настройках (около 1,2 ГБ).

### Для разработки: из исходников

```bash
./install.sh
```

Затем один раз:

1. **Универсальный доступ** → включить **65 tracker** (окно настроек откроется само). Без этого
   не будет заголовков окон, то есть имён Figma-файлов и чатов.
2. **Автоматизация** → когда macOS спросит про Chrome, разрешить: так сборщик видит URL вкладки
   (Jira-задача, Figma в браузере).
3. **Календарь** → разрешить: встречи подпишутся названиями, а офлайн-встречи засчитаются,
   даже если ноутбук простаивал.
4. Jira: `tt setup`. Токен создаётся в Jira: профиль → Personal Access Tokens. Токен вводится
   прямо в системную команду `security` и хранится в Связке ключей, не в файлах.
5. Для подсказок Claude: в терминале `claude` → `/login`, если CLI просит войти.

Проверка: `tt status`.

## Как пользоваться

| Что | Как |
|---|---|
| Разобрать день в браузере | `tt open` или кнопка «Разобрать» в утреннем напоминании |
| Разобрать с Claude | в Claude Code: `/timesheet` или «залогируй вчера» |
| Посмотреть день в терминале | `tt day вчера` |
| Отправить в Jira | кнопка «Отправить в Jira» / `tt push вчера` |
| Внести вручную | «Скопировать» / `tt export вчера`, затем «Внёс сам» / `tt mark вчера manual` |

В таймлайне у каждого блока есть поле задачи. Галочка **«запомнить»** привязывает к задаче
саму активность (этот Figma-файл, этот чат, эту встречу), и в следующие дни она разложится
автоматически. В Figma привязка запоминается на файл/проект — часть названия до « / »: «Polka / Корзина»
запомнится как «Polka», и новые экраны Polka уйдут в ту же задачу. Названия экранов остаются
в комментарии ворклога («Figma: Polka — Карточка товара, Корзина»). Без галочки привязывается только этот интервал. Чем дольше пользуетесь, тем
меньше остаётся разбирать вручную.

## Настройка — `tt config`

Пример — [config.example.json](config.example.json). Самое полезное:

```jsonc
{
  // напоминания: сколько угодно правил; review = previous_workday | today | week
  "reminders": [
    {"days": ["mon","tue","wed","thu","fri"], "time": "10:00", "review": "previous_workday"},
    {"days": ["fri"], "time": "17:00", "review": "week"}
  ],
  "reminder_style": "dialog",          // или "notification" — тихо, без окна
  "snooze_min": 60,                    // «Позже» в напоминании
  // правила (regex по app / bundle / title / url / label / any), первое совпадение побеждает
  "rules": [
    {"if": {"title": "daily|дейли|стендап"}, "issue": "INT-1"},
    {"if": {"url": "polka"}, "issue": "PL-142"},
    {"if": {"app": "YouTube"}, "category": "personal"}
  ],
  "worklog": {"round_min": 15, "min_min": 10},
  // pre_classify_on_remind: true — Claude сам размечает день перед утренним напоминанием (тратит токены)
  "llm": {"enabled": true, "auto_accept": 0.8, "pre_classify_on_remind": false},
  "jira": {"mode": "jira"}             // "tempo" — если Tempo требует обязательные атрибуты
}
```

После правки `reminders` выполните `tt agents install --reminders-only`. Остальные настройки
применяются сразу; для настроек сборщика нужен его перезапуск: `tt agents install`.

## Устройство

- `collector/main.swift` — сборщик (NSWorkspace, Accessibility, AppleScript для URL,
  CoreAudio process list для микрофона, EventKit, SQLite).
- `app/ttlib/context.py` — что делалось: Jira-ключ, Figma/Adobe-файл, чат, сайт, созвон.
- `app/ttlib/claude_sessions.py` — инкрементальный индекс сессий Claude Code (только метаданные).
- `app/ttlib/segment.py` — слоты → блоки → черновики ворклогов (largest remainder до 15 мин).
- `app/ttlib/jira.py` — Jira Server/DC REST + Tempo, проверка уже залогированного, без дублей.
- `app/ttlib/suggest.py` — `claude -p` без инструментов, строгий JSON, ключи только из ваших задач.
- `app/ttlib/server.py` + `app/web/timeline.html` — таймлайн на 127.0.0.1.
- `claude/skills/timesheet/SKILL.md` — скилл `/timesheet` (ставится в `~/.claude/skills`).
- `tests/` — синтетический день и прогон отправки против мок-Jira:
  `TT_HOME=/tmp/tt python3 tests/fake_day.py && TT_HOME=/tmp/tt python3 tests/test_push.py`.

Удаление: `./uninstall.sh` (данные останутся) или `./uninstall.sh --purge`.

## Если что-то не так

- `tt status` пишет «Заголовки окон: нет» → не выдан Универсальный доступ у 65 tracker.
  После пересборки сборщика его нужно выдать заново: `install.sh` пересобирает только при
  изменении исходника.
- Логи: `~/Library/Application Support/TimeTracker/logs/`.
- Command Line Tools бывают рассинхронизированы (Swift 6.1 против SDK 26). `install.sh` сам
  подбирает подходящий SDK и обходит дублирующийся `SwiftBridging` modulemap.
